# MCP Server Phase 1.5 — Remote Transport with OAuth Authentication

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the MCP server accessible over HTTP (not just local stdio) by mounting it as a sub-app inside the existing FastAPI backend, with OAuth 2.1 authentication that delegates to the existing Google SSO login.

**What exists:** Phase 1 delivered 5 read-only ISO tools (`iso_get_registries`, `iso_get_registry_rows`, `iso_get_documents`, `iso_get_document`, `iso_search_documents`) via stdio transport. The `mcp_server/` package at repo root imports backend models directly through `PYTHONPATH=backend`.

**What this adds:** HTTP transport on `/mcp`, OAuth 2.1 with PKCE (RFC 7636), pre-registered OAuth client (Dynamic Client Registration deferred), DB-backed OAuth state, and a cleanup job for expired tokens.

---

## 1. Context and Goals

Phase 1 works only via stdio -- Claude Code runs the MCP server as a local subprocess with a direct database connection. This is fine for a single developer but does not support:

- **Claude Desktop remote connections** (no direct DB access)
- **Multiple users** with identity-based access control
- **Deployment to production** where the MCP must be behind HTTPS

Phase 1.5 solves these by:

1. Mounting the MCP as a Starlette sub-app on the existing FastAPI backend at `/mcp`
2. Using the MCP SDK's built-in OAuth 2.1 support with an `OAuthAuthorizationServerProvider` adapter that delegates to the existing Google SSO
3. Storing OAuth clients, authorization codes, and refresh tokens in PostgreSQL
4. Running an ARQ cleanup job to purge expired OAuth artifacts

Stdio transport continues to work unchanged for local development.

---

## 2. Architecture

```
Production (HTTPS via ALB):

  Claude Desktop / Client
        |
        | HTTPS
        v
  ALB (hub.vizzuality.com)
        |
        | /mcp/* --> backend:8000
        |
  +-----+------------------------------------------------------+
  | FastAPI (backend container, port 8000)                      |
  |                                                             |
  |  /api/*          existing REST API (unchanged)              |
  |  /health/*       health checks (unchanged)                  |
  |  /metrics        prometheus (unchanged)                     |
  |                                                             |
  |  /mcp            mounted Starlette sub-app                  |
  |    /.well-known/oauth-authorization-server  (SDK route)     |
  |    /.well-known/oauth-protected-resource    (SDK route)     |
  |    /authorize    --> redirects to Google OAuth               |
  |    /token        --> issues JWT + refresh token              |
  |    /revoke       --> token revocation                        |
  |    /oauth/callback --> Google SSO callback                   |
  |    /             --> StreamableHTTP endpoint (tools)         |
  |                                                             |
  |  DB pool         shared async_session_maker (read-only)     |
  +-------------------------------------------------------------+

Local development (stdio, unchanged):

  Claude Code / Claude Desktop
        |
        | stdio
        v
  python -m mcp_server  (reads DB directly, no auth)
```

### Key architectural decisions

1. **Sub-app, not separate container.** The MCP Starlette app from `mcp.streamable_http_app()` is mounted on FastAPI via `app.mount("/mcp", mcp_starlette_app)`. Same container, same DB pool, same deploy pipeline. On a t3.micro with 2GB RAM there is no room for another container.

2. **`streamable_http_path="/"`** to avoid path doubling. FastMCP defaults to `/mcp` as the internal StreamableHTTP endpoint. When mounted at `/mcp` on FastAPI, this would create `/mcp/mcp`. Setting `streamable_http_path="/"` in `create_mcp_server()` means the tools endpoint is at `/mcp/` (the mount point itself). Clients connect to `https://hub.vizzuality.com/mcp`.

3. **RS-only + AS adapter.** The MCP SDK's `auth_server_provider` parameter takes an `OAuthAuthorizationServerProvider` implementation. Our adapter (`VizzHubOAuthProvider`) stores OAuth state in PostgreSQL and delegates user authentication to Google SSO. The `token_verifier` parameter takes a `TokenVerifier` implementation that validates the JWTs we issue.

4. **Pre-registered OAuth client, not Dynamic Client Registration.** RFC 7591 Dynamic Client Registration (`/register`) is complex and unnecessary for a team of 30. Instead, we INSERT the client record manually (or via a seed script). Claude Code/Desktop gets configured with a known `client_id`/`client_secret`. The `/register` endpoint is deferred as a future improvement.

5. **OAuth tables in PostgreSQL.** Three tables: `mcp_oauth_clients`, `mcp_oauth_codes`, `mcp_oauth_refresh_tokens`. An ARQ cron job purges expired rows daily.

6. **Read-only DB sessions preserved.** When mounted in FastAPI, MCP tools use a dedicated `mcp_read_session_maker` that shares the backend's engine but applies `execution_options={"postgresql_readonly": True}`. This preserves the Phase 1 safety guarantee at the PostgreSQL level — tools cannot accidentally write even though they share the backend's connection pool.

7. **OAuth state stored in DB, not JWT.** The `/authorize` flow stores MCP parameters (code_challenge, redirect_uri, scopes, client_id, state) in a temporary DB row (5-minute TTL) and passes only the row ID in Google OAuth's `state` parameter. This avoids URL length limits (~2048 chars) and doesn't expose MCP parameters in the browser URL.

```sql
-- Dynamic client registrations (RFC 7591)
CREATE TABLE IF NOT EXISTS mcp_oauth_clients (
    client_id       VARCHAR(128) PRIMARY KEY,
    client_secret   VARCHAR(256),
    client_info     JSONB NOT NULL,           -- full OAuthClientInformationFull serialized
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at      TIMESTAMPTZ              -- NULL = never expires
);

-- Authorization codes (60-second TTL)
CREATE TABLE IF NOT EXISTS mcp_oauth_codes (
    code            VARCHAR(256) PRIMARY KEY,
    client_id       VARCHAR(128) NOT NULL REFERENCES mcp_oauth_clients(client_id) ON DELETE CASCADE,
    code_challenge  VARCHAR(256) NOT NULL,    -- PKCE S256
    redirect_uri    TEXT NOT NULL,
    scopes          JSONB,                    -- ["read"] or null
    user_id         UUID REFERENCES users(id),
    user_email      VARCHAR(255),
    user_roles      JSONB,                    -- ["user", "admin"]
    user_permissions JSONB,                   -- ["*"] or ["iso.read", ...]
    resource        TEXT,                     -- RFC 8707 resource indicator
    expires_at      TIMESTAMPTZ NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Refresh tokens (30-day default TTL)
CREATE TABLE IF NOT EXISTS mcp_oauth_refresh_tokens (
    token           VARCHAR(256) PRIMARY KEY,
    client_id       VARCHAR(128) NOT NULL REFERENCES mcp_oauth_clients(client_id) ON DELETE CASCADE,
    user_id         UUID REFERENCES users(id),
    user_email      VARCHAR(255),
    user_roles      JSONB,
    user_permissions JSONB,
    scopes          JSONB,
    resource        TEXT,
    expires_at      TIMESTAMPTZ NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS ix_mcp_oauth_codes_expires
    ON mcp_oauth_codes(expires_at);
CREATE INDEX IF NOT EXISTS ix_mcp_oauth_refresh_tokens_expires
    ON mcp_oauth_refresh_tokens(expires_at);
```

### Phase B: OAuth Provider Adapter

#### Task B1: VizzHubOAuthProvider

**Files:**
- Create: `mcp_server/auth/__init__.py`
- Create: `mcp_server/auth/provider.py`

This is the core of the auth integration. It implements `OAuthAuthorizationServerProvider` from the MCP SDK and bridges to the existing Google SSO flow.

The provider needs its own writable DB sessions (not the read-only sessions from `mcp_server/data/base.py`). It will import `async_session_maker` from `app.database` directly, since the MCP sub-app runs inside the backend process and shares the same DB pool.

**Key methods:**

| Method | What it does |
|--------|-------------|
| `get_client(client_id)` | SELECT from `mcp_oauth_clients` |
| `register_client(client_info)` | **Deferred.** For now, return the pre-registered client if `client_id` matches, else None. Phase 1.5 uses a manually-inserted client row. |
| `authorize(client, params)` | Redirect to Google OAuth with `state` encoding the MCP params (code_challenge, redirect_uri, scopes, client_id). The callback must be a backend route. |
| `load_authorization_code(client, code)` | SELECT from `mcp_oauth_codes` WHERE code AND client_id, check not expired |
| `exchange_authorization_code(client, auth_code)` | Delete code row, create access JWT + refresh token, INSERT refresh token row, return `OAuthToken` |
| `load_refresh_token(client, token)` | SELECT from `mcp_oauth_refresh_tokens` WHERE token AND client_id, check not expired |
| `exchange_refresh_token(client, refresh_token, scopes)` | Delete old refresh token, create new access JWT + new refresh token, INSERT new refresh token row, return `OAuthToken` |
| `load_access_token(token)` | Decode JWT locally (same `jwt_secret_key` from `app.config`), return `AccessToken` if valid |
| `revoke_token(token)` | DELETE from `mcp_oauth_refresh_tokens` (and/or mark access token as revoked) |

**The `authorize` flow in detail:**

```
1. MCP SDK calls provider.authorize(client, params)
   params contains: code_challenge, redirect_uri, scopes, state

2. Provider stores MCP params in a temporary DB row (5-minute TTL):
   INSERT INTO mcp_oauth_codes (code, client_id, code_challenge, redirect_uri,
     scopes, resource, expires_at)
   VALUES (random_state_id, client_id, params.code_challenge,
     params.redirect_uri, params.scopes, params.resource, now() + 5min)
   Note: user_id is NULL at this point — filled in by the callback.

3. Provider builds a Google OAuth URL:
   - Uses existing settings.google_client_id
   - redirect_uri = f"{base_url}/mcp/oauth/callback" (our custom route)
   - state = random_state_id (just a DB row ID, not a JWT blob)
   This avoids URL length limits (~2048 chars) and doesn't expose
   MCP parameters in the browser URL.
4. Provider returns the Google OAuth URL

5. User authenticates with Google -> Google redirects to /mcp/oauth/callback

6. Callback handler:
   a. Extracts state (= DB row ID) from Google callback params
   b. Exchanges Google auth code for ID token
   c. Verifies ID token, extracts email, checks domain restriction
      (same logic as existing google_auth endpoint: id_token.verify_oauth2_token,
       email.split("@")[-1] == allowed_google_domain)
   d. Looks up VizzHub user, loads roles + permissions
   e. Updates the mcp_oauth_codes row: sets user_id, user_email, user_roles,
      user_permissions, resets expires_at to now() + 60s (short auth code TTL)
   f. Generates a NEW authorization_code (secrets.token_urlsafe(32))
   g. Redirects to stored redirect_uri?code={auth_code}&state={mcp_state}

7. MCP client calls /mcp/token with the code
   -> SDK calls provider.exchange_authorization_code()
   -> Provider verifies PKCE, creates JWT + refresh token, returns OAuthToken
```

#### Task B3: VizzHubTokenVerifier

**Files:**
- Create: `mcp_server/auth/token_verifier.py`

Implements the `TokenVerifier` protocol from `mcp.server.auth.middleware.bearer_auth`. This is simpler than the full provider -- it just decodes JWTs.

```python
from mcp.server.auth.middleware.bearer_auth import TokenVerifier, AccessToken

class VizzHubTokenVerifier:
    """Verify MCP access tokens (JWTs signed with the backend's secret)."""

    def __init__(self, secret_key: str, algorithm: str = "HS256") -> None:
        self._secret_key = secret_key
        self._algorithm = algorithm

    async def verify_token(self, token: str) -> AccessToken | None:
        try:
            payload = jwt.decode(token, self._secret_key, algorithms=[self._algorithm])
            return AccessToken(
                token=token,
                client_id=payload.get("client_id", "unknown"),
                scopes=payload.get("scopes", []),
                expires_at=payload.get("exp"),
            )
        except JWTError:
            return None
```

        token_verifier=token_verifier,
        auth=auth_settings,
        **kwargs,
    )

    # Register tools (same for both transports)

    return mcp

# Default instance for stdio (backward compatible)
mcp = create_mcp_server()

### Phase E: MCP Data Layer Adaptation

#### Task E1: Read-only DB session sharing for HTTP mode

**Files:**
- Modify: `mcp_server/data/base.py`

When running as a sub-app inside FastAPI, the MCP tools should use the backend's engine but with **read-only sessions** to preserve the Phase 1 safety guarantee. We create a dedicated `async_session_maker` that shares the backend's engine but applies `execution_options={"postgresql_readonly": True}`.

```python
_backend_read_session_maker: async_sessionmaker | None = None

def enable_backend_sessions() -> None:
    """Create a read-only session maker sharing the backend's engine."""
    global _backend_read_session_maker
    from app.database import engine  # backend's existing engine
    from sqlalchemy.ext.asyncio import async_sessionmaker, AsyncSession
    _backend_read_session_maker = async_sessionmaker(
        engine,
        class_=AsyncSession,
        expire_on_commit=False,
        execution_options={"postgresql_readonly": True},
    )

@asynccontextmanager
async def get_read_session() -> AsyncGenerator[AsyncSession, None]:
    override = _session_override.get()
    if override is not None:
        yield override
        return

    if _backend_read_session_maker is not None:
        async with _backend_read_session_maker() as session:
            yield session
            return

    maker = _get_session_maker()
    async with maker() as session:
        yield session
```

The `postgresql_readonly` execution option is preserved at the PostgreSQL level — even though we share the backend's engine, the MCP sessions cannot accidentally write. This maintains the Phase 1 safety guarantee.

- [ ] **Step 1:** Add `enable_backend_sessions()` function that creates a read-only session maker from the backend's engine.
- [ ] **Step 2:** Update `get_read_session()` to use `_backend_read_session_maker` when set.
- [ ] **Step 3:** Call `enable_backend_sessions()` in `main.py` when mounting the MCP sub-app.

**Validation:** Existing stdio tests still pass (they use the override mechanism). Tools work when mounted in FastAPI. A test that tries to `session.execute(insert(...))` through the MCP session maker raises a read-only error.

## 6. Risks and Mitigations

| Risk | Severity | Mitigation |
|------|----------|------------|
| **Google OAuth callback URL registration** | MEDIUM | Must be registered in Google Cloud Console before production deploy. Document in deployment checklist. Test locally with `http://localhost:8000/mcp/oauth/callback`. |
| **PKCE code_verifier validation** | MEDIUM | The SDK's token handler sends the `code_verifier`; our provider must verify it against the stored `code_challenge` using S256. Must implement correctly or auth will silently fail. Use the standard: `base64url_encode(sha256(code_verifier)) == code_challenge`. |
| **Starlette lifespan conflict with FastAPI** | MEDIUM | The MCP SDK's `streamable_http_app()` creates a Starlette app with its own lifespan (session manager). When mounted as a sub-app of FastAPI, both lifespans must work. FastAPI handles sub-app lifespans correctly per Starlette spec. Test that both start/stop cleanly. |
| **Shared DB pool contention** | LOW | The MCP sub-app reuses the backend's engine. MCP traffic is low-volume (LLM tool calls). No risk of pool exhaustion. |
| **JWT secret shared between API and MCP** | LOW | Both use `settings.jwt_secret_key`. Intentional — same process. |

### Risks resolved by design

| Risk | Resolution |
|------|-----------|
| **Path doubling `/mcp/mcp`** | `streamable_http_path="/"` in `create_mcp_server(http_mode=True)`. Verified: FastMCP accepts this parameter. Clients connect to `/mcp`. |
| **Dynamic Client Registration complexity** | Deferred entirely. Pre-registered client via manual DB INSERT. `/register` returns the pre-registered client if ID matches, else None. |
| **Read-write DB in HTTP mode** | `enable_backend_sessions()` creates a session maker with `execution_options={"postgresql_readonly": True}` sharing the backend's engine. Safety guarantee preserved at PostgreSQL level. |
| **OAuth state URL length limits** | State stored in DB row (5-minute TTL), only row ID in Google's `state` param. No JWT blob in URL. |

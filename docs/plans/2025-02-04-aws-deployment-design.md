# AWS Deployment Design

## Overview

First production deployment of Project Scorecard to AWS. Single EC2 instance running Docker Compose with RDS PostgreSQL.

**Target URL:** `https://hub.vizzuality.com`

## Infrastructure Components

| Component | Specification | Monthly Cost (On-Demand) |
|-----------|--------------|-------------------------|
| EC2 | t3.medium (x86) | ~$30 |
| RDS | db.t4g.small, PostgreSQL 16 | ~$23 |
| RDS Storage | 20GB gp3 | ~$2.30 |
| Secrets Manager | ~5 secrets | ~$2 |
| Elastic IP | Associated to EC2 | $0 |
| SSM Session Manager | - | $0 |
| **Total** | | **~$58** |

With Reserved Instances (1 year): **~$39/month**

## Network Design

```
VPC 10.0.0.0/16
│
├── Public Subnet 10.0.1.0/24 (AZ-a)
│   ├── EC2 instance
│   ├── Route: 0.0.0.0/0 → IGW
│   └── Elastic IP attached
│
├── Private Subnet 10.0.10.0/24 (AZ-a)
│   ├── RDS (primary)
│   └── Route: local only (no internet)
│
└── Private Subnet 10.0.11.0/24 (AZ-b)
    └── RDS (subnet group requires 2 AZs)
```

### Security Groups

| Security Group | Inbound | Outbound |
|----------------|---------|----------|
| `sg-ec2` | 443 from 0.0.0.0/0 | All (ECR, Secrets Manager, etc.) |
| `sg-rds` | 5432 from `sg-ec2` only | All (AWS default) |

### Access Model

- **Web:** HTTPS only (port 443), Google SSO with domain restriction
- **Admin:** SSM Session Manager (no SSH, port 22 closed)
- **RDS:** Only from EC2 via private network

## CI/CD Pipeline

### Flow

```
Push to main ──► Tests ──► Build Images ──► Push to ECR ──► Deploy via SSM
                  │                                              │
                  └── Manual trigger also available              │
                                                                 ▼
                                                    EC2: pull + restart + healthcheck
                                                                 │
                                                    Fail? ──► Rollback to previous tag
```

### GitHub Actions Configuration

**Variables (Settings → Actions → Variables):**
- `AWS_ACCOUNT_ID`
- `AWS_REGION` (eu-west-1)
- `EC2_INSTANCE_ID`

**Authentication:** OIDC (no access keys stored)

### Deploy Process

1. GitHub Actions assumes IAM role via OIDC
2. Builds and pushes images to ECR with SHA tag
3. Sends command to EC2 via SSM `send-command`
4. Polls for completion with `get-command-invocation`
5. EC2 runs `deploy.sh`:
   - Pulls new images
   - Restarts containers
   - Runs healthchecks
   - Rolls back if healthcheck fails

## Docker Compose (Production)

```yaml
services:
  nginx:
    image: nginx:alpine
    container_name: hub-nginx
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certbot/config:/etc/letsencrypt:ro

  frontend:
    image: ${ECR_URI}/frontend:${TAG:-latest}
    container_name: hub-frontend
    expose:
      - "5173"

  backend:
    image: ${ECR_URI}/backend:${TAG:-latest}
    container_name: hub-backend
    expose:
      - "8000"
    env_file:
      - .env.prod
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379

  worker:
    image: ${ECR_URI}/backend:${TAG:-latest}
    container_name: hub-worker
    command: arq app.worker.settings.WorkerSettings
    env_file:
      - .env.prod
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379

  redis:
    image: redis:7-alpine
    container_name: hub-redis
    # No volume: volatile by design (jobs can be re-queued)
```

## SSL/TLS with Let's Encrypt

### Initial Certificate

Obtained during EC2 first boot via `user_data.sh`:

```bash
certbot certonly --standalone \
  -d hub.vizzuality.com \
  --config-dir /opt/hub/certbot/config \
  --work-dir /opt/hub/certbot/work \
  --logs-dir /opt/hub/certbot/logs
```

**Prerequisite:** DNS must resolve to EC2's Elastic IP before certbot runs.

### Automatic Renewal

Cron job at 3:00 AM daily:

```bash
certbot renew \
  --config-dir /opt/hub/certbot/config \
  --work-dir /opt/hub/certbot/work \
  --logs-dir /opt/hub/certbot/logs \
  --quiet \
  --deploy-hook "docker exec hub-nginx nginx -s reload >> /var/log/hub/certbot-reload.log 2>&1 || true"
```

## Deployment Checklist

### First-Time Setup

```
1. BOOTSTRAP (once, manual)
   ├── cd infrastructure/bootstrap
   ├── tofu init
   ├── tofu apply
   └── Save outputs (bucket name, table name)

2. INFRASTRUCTURE
   ├── cd infrastructure/
   ├── Configure backend.tf with bootstrap outputs
   ├── tofu init
   ├── tofu plan -var-file=environments/prod.tfvars
   ├── tofu apply -var-file=environments/prod.tfvars
   └── Save outputs:
       ├── EC2 Instance ID
       ├── Elastic IP
       ├── RDS endpoint
       └── ECR URI

3. DNS (manual - BEFORE certbot runs)
   ├── Create A record: hub.vizzuality.com → [Elastic IP]
   ├── Verify propagation: dig hub.vizzuality.com
   └── IMPORTANT: Must resolve BEFORE step 5

4. SECRETS
   ├── Auto-generated by OpenTofu (DO NOT EDIT):
   │   ├── /hub/prod/db-password
   │   └── /hub/prod/jwt-secrets
   │
   └── Manual (fill in AWS Console):
       ├── /hub/prod/google-oauth
       ├── /hub/prod/jira-oauth
       ├── /hub/prod/github
       └── /hub/prod/slack (optional)

5. FIRST EC2 BOOT
   ├── user_data.sh runs automatically
   ├── Installs Docker, certbot, etc.
   ├── Obtains SSL certificate (requires DNS working)
   └── If certbot fails (DNS not ready), run manually:

       # Connect via SSM (no SSH available)
       aws ssm start-session --target i-xxxxx

       # Run certbot
       sudo certbot certonly --standalone \
         -d hub.vizzuality.com \
         --config-dir /opt/hub/certbot/config \
         --work-dir /opt/hub/certbot/work \
         --logs-dir /opt/hub/certbot/logs

6. GITHUB CONFIGURATION
   ├── Settings → Secrets and variables → Actions
   ├── Variables:
   │   ├── AWS_ACCOUNT_ID
   │   ├── AWS_REGION (eu-west-1)
   │   └── EC2_INSTANCE_ID
   └── (No secrets needed: OIDC handles auth)

7. FIRST DEPLOY
   ├── Push to main (or manual workflow_dispatch)
   ├── CI runs tests
   ├── Build + push to ECR
   ├── SSM executes deploy.sh
   └── Verify https://hub.vizzuality.com
```

### Post-Deploy Verification

```bash
# Connect to EC2 via SSM
aws ssm start-session --target i-xxxxx

# Check running services
docker compose -f /opt/hub/docker-compose.prod.yml ps

# Check logs
docker compose -f /opt/hub/docker-compose.prod.yml logs -f

# Verify SSL certificate
openssl s_client -connect hub.vizzuality.com:443 \
  -servername hub.vizzuality.com </dev/null 2>/dev/null | \
  openssl x509 -noout -dates -issuer -subject

# Verify database connectivity
docker exec hub-backend python -c "
from sqlalchemy import text
from app.database import engine
with engine.connect() as conn:
    result = conn.execute(text('SELECT 1'))
    print('DB OK:', result.fetchone())
"
```

### Manual Rollback

```bash
# Connect via SSM
aws ssm start-session --target i-xxxxx

# Load configuration
source /opt/hub/.env.infra

# Check current and previous tags
cat /opt/hub/.current-tag

# Rollback to specific tag
cd /opt/hub
export TAG="abc123"  # Previous SHA
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d

# Verify
docker compose -f docker-compose.prod.yml ps
```

## Design Decisions

| Decision | Rationale | Trade-off |
|----------|-----------|-----------|
| EC2 + Compose (not ECS/EKS) | Cost optimization (~$58 vs ~$100+) | No auto-scaling |
| t3.medium x86 (not ARM) | Simpler first deploy | ~20% more expensive than t4g |
| RDS (not PostgreSQL on EC2) | Managed backups, maintenance | ~$25/month extra |
| Redis on EC2 (not ElastiCache) | Jobs are non-critical | Data lost on restart |
| Public subnet (no NAT/endpoints) | Cost savings (~$30/month) | EC2 has public IP |
| SSM (no SSH) | Better security, audit logs | Requires AWS CLI |
| `container_name` fixed | Stable deploy-hook for certbot | No horizontal scaling |
| OIDC (no access keys) | No long-lived credentials | Slightly complex setup |
